# 2026-11-17-01: a working method for r2c, and mechanical checks

Who: the developer (a coding agent); the owner set the direction, then left it unattended.
Branch at the end: `method` (not merged).

## Goal

After reviewing the one-shot build (2026-11-15-01), and another project's way of working with
a coding agent, the owner asked for two changes:

- restructure the repository for a working method: instruction hierarchy, acceptance,
  session logs, status in the repository, the lost diagnostic tools, the timing correction;
- mechanize tool-level QC: generated verification results, checks on push, a recipe for
  rebuilding the oracle archive.

## Done

- `CLAUDE.md`: roles, instruction hierarchy, session start and end, commit as you go,
  provenance marking, where things are.
- `docs/acceptance.md`: the owner's stance, the open structural questions, a machine-read
  toml block of tolerances (all unset).
- `docs/log/`: template, a reconstructed log of the 2026-11-15 build, this log.
- `docs/status.md`: the end-of-build record moved into the repository and brought up to date.
- `tools/diagnose.py`: the two diagnostics rebuilt (`states`, `controls`). `run.setup()` split
  out of `run.solve()` so they set up an analysis exactly as a solve does.
- `tools/capture.py`: rebuilds the oracle archive from the fixtures' headers and checks each
  capture against its fixture. Dry run only.
- `tools/verify.py` records run.json; `tools/report.py` writes `docs/verification-results.md`
  and `.json`; `tools/check.py` checks acceptance parses, results are as generated and current,
  and logs have their sections.
- `.github/workflows/tests.yml`: fast tests and `check.py` on push (Python 3.11 and 3.13).
- README and `docs/verification.md`: the misleading timing comparison corrected; verification.md
  now interprets the generated results instead of carrying hand-written tables.
- After the owner's review: the repository's instructions and docs made impersonal (roles
  "owner" and "developer"; no names, no particular machines). Personal working arrangements
  are kept outside the repository (owner, 2026-11-18).

  **For the owner to confirm.**
